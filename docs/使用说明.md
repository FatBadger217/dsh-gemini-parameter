# 使用说明 — dsh-gemini-parameter 0.1.1

[English](../README.md) | [简体中文](../README.zh-CN.md)

面向日常使用：确认它在工作、按字段查配置（§3 字段手册）、处理常见疑问。安装与环境要求见 [`../README.zh-CN.md`](../README.zh-CN.md)；版本历史见 [`../CHANGELOG.md`](../CHANGELOG.md)。

## 0. 用途、边界与免责声明（务必先读）

> **本插件不是破甲插件。**

- 本插件透传的是 Google 官方 API 明确支持的 `safetySettings` 参数（阈值可设 `BLOCK_NONE` / `BLOCK_ONLY_HIGH` 等），用途是**让 Google 官方在内容安全判定上对敏感内容放宽限制**。这是受到 Google 官方支持的配置项，不是绕过、破解或修改模型本身。
- 它不包含任何提示词注入、角色扮演、编码绕过，**不替代也不属于破甲**。
- **破甲相关提示词很容易触发 Google 官方云端掐断**：请求可能被直接终止（流中断、`finishReason` 异常、`429`/安全拒绝）。这是上游行为，本插件无法改变，也不保证此类请求能通过。
- **降低安全性绝不意味着可以用 Gemini 生成任何严重违法犯罪内容**：CSAM（儿童性虐待内容）、暴恐、严重暴力等在任何阈值下都无法通过 Google 的强制拦截；尝试生成会导致账号封禁，并可能承担法律责任。
- **免责声明**：本插件只做 Google 官方参数透传。**使用者若尝试用本插件从事任何违法犯罪行为，一切后果由使用者自负，与作者无关。**

## 1. 它解决什么问题

DSH 的原生 `google` 路由（pi-ai + `@google/genai`）构造请求时只填 `model / contents / config` 里的少量字段。Google 官方 `GenerateContentRequest` 里的许多参数——安全阈值、`serviceTier`、`cachedContent`、`maxOutputTokens` 覆盖、`mediaResolution` 等——DSH 没有设置入口，pi-ai 也不提供 payload 钩子。

本插件在宿主进程里包装 `globalThis.fetch`，只对 `generativelanguage.googleapis.com` 上 `:generateContent` / `:streamGenerateContent` 的 JSON 请求做**白名单式参数透传**，不改任何官方安装包。

三组透传项**互相独立**，可以只开其中一组（完整字段手册见 §3）：

| 透传项 | 配置键 | 默认 | 关闭方式 |
|---|---|---|---|
| `safetySettings`（安全阈值） | `safetySettings` | 四类 `BLOCK_NONE` | `safetySettings: false` |
| `X-Server-Timeout` 头 | `serverTimeoutSeconds` | `1200` | `null` 或 `0` |
| 其它官方请求字段 | `officialParams` | 空（不注入） | 不写，或 `officialParams: {}` |

## 2. 确认是否生效

三种证据，按从强到弱：

1. **调试落盘（最强）**：把 `debugDumpTo` 设成一个临时文件路径，重启后发一次原生 google 请求，文件里会出现类似
   ```json
   {"time":"2026-11-21T18:00:00.000Z","instance":"ab12cd34","call":1,"url":"https://generativelanguage.googleapis.com/v1beta/models/gemini-4-carbon:streamGenerateContent?alt=sse","status":200,"injected":true,"mode":"merge","xServerTimeout":"1200","safetySettings":[{"category":"HARM_CATEGORY_HARASSMENT","threshold":"BLOCK_NONE"}],"officialParams":null}
   ```
   （`safetySettings` 示例截断，实际四类各一条。）`injected: true` 表示至少有一组参数被写入；`safetySettings: null` 表示该组已关闭；`officialParams` 非 `null` 时是实际注入的字段；`status: 200` 表示上游接受。
2. **宿主日志**：`log: true` 时，每次注入打印一行（含注入了哪几组、URL）。`dsh web` 的日志在启动终端/日志文件里。
3. **配置回读**：`dsh --profile <名称> --dump-config | Select-String gemini-parameter` 能看到行与完整 config；`plugin_manager list_plugins` 里该行 `fiberPhase: active` 表示已在运行宿主中挂载。

> 一个 step 出现 2 条 dump 是正常的：DSH 除主对话请求外，还会用同一默认模型发一次会话标题生成请求（`session-title-llm`），两个请求都会带上配置。

## 3. 字段手册

### 3.1 配置写在哪里、怎么生效

- 配置写在**插件包自身的 `cordis.patch.yml`** 的 `config:` 段（随包安装，**不在 profile 层**）。
- **改配置首选插件详情页的配置面板**（0.1.0 起，见 §3.12）；手工编辑配置文件也可以。
- **改完必须重启 `dsh web`**：插件在挂载期读取并校验一次配置，运行中改文件不会热生效。
- **配置不在 `~/.dsh/profiles/<名称>/cordis.patch.yml`**（Windows 为 `<用户目录>\.dsh\profiles\<名称>\cordis.patch.yml`）——那是 profile 层补丁，只用于停用插件行（见 §6）；把配置写进那里不会生效。
- 安装位置：执行 `dsh plugin --profile <名称> add github:FatBadger217/dsh-gemini-parameter` 后，插件落盘在 `~/.dsh/profiles/<名称>/node_modules/dsh-gemini-parameter\`（Windows 为 `<用户目录>\.dsh\profiles\<名称>\node_modules\dsh-gemini-parameter\`），上述配置文件即该目录内的 `cordis.patch.yml`。
- 字段一览（默认值）：

| 字段 | 类型 | 默认值 | 一句话 |
|---|---|---|---|
| `hosts` | 字符串/数组 | `['generativelanguage.googleapis.com']` | 命中主机，`*.` 通配 |
| `endpoints` | 数组 | `[':generateContent', ':streamGenerateContent']` | 路径后缀匹配 |
| `safetySettings` | `false`/数组/对象 | 四类 `BLOCK_NONE` | 安全阈值注入 |
| `mode` | 枚举 | `merge` | `safetySettings` 注入方式 |
| `serverTimeoutSeconds` | 整数/`null` | `1200` | `X-Server-Timeout` 头 |
| `officialParams` | 对象 | `{}` | 其它官方字段白名单透传 |
| `debugDumpTo` | 路径/`null` | `null` | JSONL 调试转储 |
| `log` | 布尔 | `false` | 每次注入一行日志 |
| `onUnsupportedBody` | 枚举 | `skip` | 不支持请求体的处置 |

非法配置（类型错误、枚举拼错、白名单外键等）一律在**挂载期直接抛错**，插件不挂载——这是刻意设计：宁可启动失败，也不把拼错的参数静默发给 Google。

### 3.2 `hosts` — 命中主机

- **含义**：请求 URL 的主机名只有命中 `hosts` 才会被处理；未命中的请求连 body 都不读，直接透传。
- **数据类型**：字符串或字符串数组（单个时可不列表）。
- **取值范围**：每项是一个**精确域名**；允许 `*.` 前缀通配——`'*.googleapis.com'` 匹配去掉通配符后的 `googleapis.com` 本身与任意子域名。YAML 里 `*` 开头的标量必须加引号。
- **默认值**：`['generativelanguage.googleapis.com']`（AI Studio 端点）。
- **怎么改**：

  ```yaml
  hosts:
    - generativelanguage.googleapis.com
    - '*.googleapis.com'
  ```

- **改了会怎样**：只改请求匹配范围，不影响注入内容。**通配过宽会把无关 Google 流量也纳入处理**（虽仍只注入白名单字段，但排障面变大）；改窄则可能不再命中。
- **常见错误**：写成带 `https://` 协议或带路径的字符串——不报错，但**永不命中、静默不生效**；首要特征是 `debugDumpTo` 文件没有新行。无上游 400 风险（不命中就不发）。

### 3.3 `endpoints` — 命中端点

- **含义**：主机命中后，再按 URL 路径**后缀**匹配；两个条件都命中才处理该请求。
- **数据类型**：字符串数组。
- **取值范围**：每项必须以 `:` 开头且 ≥2 字符（如 `:generateContent`）；按后缀匹配，所以 `:generateContent` 能命中 `.../models/gemini-xxx:generateContent`。
- **默认值**：`[':generateContent', ':streamGenerateContent']`。
- **怎么改**：

  ```yaml
  endpoints:
    - ':generateContent'
    - ':streamGenerateContent'
  ```

- **改了会怎样**：默认不含 `:countTokens`、`:embedContent`、`files` 上传等端点；**若自行加入，这些端点不一定接受注入的字段，可能上游 400**。
- **常见错误**：忘写开头冒号、或只剩 `:` 一个字符——**挂载期直接抛错**，dsh web 启动日志出现 `[gemini-parameter]` 报错、插件行不 active。

### 3.3a `relayUnwrap` — 代理兼容（billion-context 等改写型插件）

- **含义**：识别"代理改写型"插件交下来的请求。billion-context 等宿主内代理会把模型请求改写成 `http://127.0.0.1:端口/bili/https://generativelanguage.googleapis.com/...` 再送入 fetch 链——原始主机名已经不在主机位上，按 `hosts` 匹配会静默失效。开启本项后，插件从路径中解出内嵌的原始网址，按它做主机+端点匹配并照常注入。
- **通用配置方法**（适用于任何会改写请求网址的插件，不限于 billion-context）：
  1. 兼容未开启时，面板统计出现"代理改写（未兼容）"计数并显示警告卡片——这就是症状；
  2. 到该插件的文档或日志里确认它把网址改写成了什么形状，取出它插入的**路径前缀**（billion-context 是 `/bili/`）；
  3. 面板「编辑配置 → 网络匹配」给 `relayUnwrap` 添加该前缀并保存（或按下方 YAML 手改），重启 `dsh web`；
  4. 重启后警告消失、统计恢复计数即成功。概览卡（当前生效配置）会显示已启用的前缀，并对已知前缀标注对应插件（`/bili/` → billion-context）。
- **数据类型**：字符串数组（路径前缀）。
- **取值范围**：每项以 `/` 开头且 ≥2 字符；billion-context 用 `'/bili/'`。
- **默认值**：`[]`（**关闭**——不影响未装代理插件的用户）。
- **怎么改**（装了 billion-context 时；其它改写型插件换成它的前缀）：

  ```yaml
  relayUnwrap:
    - '/bili/'
  ```

- **改了会怎样**：本地代理改写后的 Gemini 请求重新被识别并注入；面板统计恢复计数。注意 `/bili/` 是 billion-context 的**内部 URL 约定**（上游讨论 [billion-context#7527](https://github.com/ranxianglei/billion-context/issues/7527)），其改版可能需要同步更新此前缀。
- **常见错误**：面板出现"检测到代理改写"警告却一直不开启本项——注入不会生效；或前缀忘写 `/`——**挂载期直接抛错**。
- **自查**：`debugDumpTo` 落盘行里的 `url` 是本地代理地址（127.0.0.1）属正常现象，注入内容照常记录在 `safetySettings`/`officialParams` 字段中。

### 3.4 `safetySettings` — 安全阈值

- **含义**：注入 Google 官方 `safetySettings`（内容安全阈值）。**`BLOCK_NONE` 是 Google 官方最低限制档——官方支持的设置，不是破解**；不写则保持 Google 默认（较严格）限制。
- **数据类型与 5 种写法**：
  1. `false`：**整组关闭**——不注入任何 safetySettings；
  2. 不写 / `null`：按默认注入四类 `BLOCK_NONE`；
  3. 数组：元素为 `{category, threshold}` 对象，或**纯字符串** `"类别名"`（= 该类 `BLOCK_NONE`）；也接受大写 `Category` / `Threshold` 键变体；
  4. 对象映射：`{HARM_CATEGORY_XXX: 阈值}`。
- **取值范围**：
  - category：必须 `HARM_CATEGORY_` 前缀 + 大写字母/数字/下划线；**同一类别出现两次会在挂载期报错**。
  - threshold 六档枚举：

    | 值 | 档位 |
    |---|---|
    | `HARM_BLOCK_THRESHOLD_UNSPECIFIED` | 未指定 |
    | `BLOCK_LOW_AND_ABOVE` | 拦截低及以上风险 |
    | `BLOCK_MEDIUM_AND_ABOVE` | 拦截中及以上风险 |
    | `BLOCK_ONLY_HIGH` | 只拦截高风险 |
    | `BLOCK_NONE` | 不拦截（官方最低限制档） |
    | `OFF` | 关闭 |
- **默认值**：四类 `HARM_CATEGORY_HARASSMENT` / `HARM_CATEGORY_HATE_SPEECH` / `HARM_CATEGORY_SEXUALLY_EXPLICIT` / `HARM_CATEGORY_DANGEROUS_CONTENT` 全部 `BLOCK_NONE`。
- **怎么改**：

  ```yaml
  # 整组关闭（保持 Google 默认较严格限制）
  safetySettings: false

  # 对象映射：只放宽骚扰与危险内容两类
  safetySettings:
    HARM_CATEGORY_HARASSMENT: BLOCK_NONE
    HARM_CATEGORY_DANGEROUS_CONTENT: BLOCK_ONLY_HIGH

  # 数组：完整写法（也接受 Category/Threshold 大写键变体）
  safetySettings:
    - category: HARM_CATEGORY_HATE_SPEECH
      threshold: BLOCK_NONE
    - category: HARM_CATEGORY_SEXUALLY_EXPLICIT
      threshold: BLOCK_NONE

  # 数组：纯字符串 = 该类 BLOCK_NONE
  safetySettings:
    - HARM_CATEGORY_HARASSMENT
    - HARM_CATEGORY_HATE_SPEECH
  ```

- **改了会怎样**：注入方式由 `mode` 决定（见 §3.5）；与 `serverTimeoutSeconds`、`officialParams` 互不影响。
- **常见错误与 400 特征**：类别/阈值枚举拼错、类别不带前缀或含小写、重复类别 → **挂载期抛错**；类别或阈值不被该模型支持 → 上游 **400 `INVALID_ARGUMENT`，消息点名 `safetySettings`**——先删该类别或把阈值降一档（如 `BLOCK_ONLY_HIGH`）再试。

### 3.5 `mode` — `safetySettings` 注入方式

- **含义**：只影响 `safetySettings` 怎么并入请求，与其它两组透传无关。
- **数据类型**：字符串枚举。
- **取值范围**：
  - `merge`（默认）：请求已带的类别**保留原位**，配置里的阈值**覆盖**该类（类别对象上额外的键保留），缺失类别**按配置顺序追加**；
  - `replace`：**整表替换**——请求自带的 `safetySettings` 全部丢弃，换成配置表；
  - `insert-only`：请求已带**任何** `safetySettings` 就完全不动；只有请求一条都没带时才注入。
- **默认值**：`merge`。
- **怎么改**：

  ```yaml
  mode: replace
  ```

- **改了会怎样**：若 DSH/SDK 某天自带了 `safetySettings`，`merge` 覆盖其阈值、`insert-only` 尊重 SDK 原值、`replace` 连表都换成配置的。想验证注入链路时，临时用 `replace` 最直观。
- **常见错误**：把 `insert-only` 理解成“追加”——它是“请求里已有就一字不动”；写了枚举外的值 → 挂载期抛错。无上游 400 风险。

### 3.6 `serverTimeoutSeconds` — 超时头

- **含义**：以 `X-Server-Timeout` 请求头发送服务端处理时限（秒）。**该头在 AI Studio 端点（`generativelanguage.googleapis.com`）上的语义 Google 未公开**；实测该端点接受 `1200` 与 `200`，值 `0` 会返回 400。Vertex AI 官方语义为 1..1200 秒。
- **数据类型**：整数，或 `null` / `false` / `0`。
- **取值范围**：不写 = 默认 `1200`（Vertex 上限）；**`0` / `null` / `false` = 不发送该头**；其余必须是 **1..1200 的整数**。
- **默认值**：`1200`。
- **怎么改**：

  ```yaml
  serverTimeoutSeconds: 600   # 改成 600 秒
  serverTimeoutSeconds: null  # 关闭该头（0/false 同义）
  ```

- **改了会怎样**：请求**已带 `X-Server-Timeout` 头时不覆盖**（尊重调用方）。关闭方式是让插件根本不发这个头，**不是发 0**——实测该端点收到 0 值会直接 400。
- **常见错误与 400 特征**：非整数（如 `600.5`）、超出 1..1200 → 挂载期抛错；上游 400 指向该头时，把 `serverTimeoutSeconds` 设 `null` 复测即可定位。

### 3.7 `officialParams` — 其它官方字段

- **含义**：白名单式透传 `GenerateContentRequest` 的其它官方字段。**未知键在插件挂载时直接抛错**——避免拼错的字段被静默发给 Google。
- **数据类型**：对象；所有值必须 **JSON 可序列化**。
- **取值范围**：顶层白名单 5 键：`generationConfig` / `serviceTier` / `cachedContent` / `labels` / `toolConfig`。`generationConfig` 必须是非空对象，子键白名单 19 个：

  `temperature`、`topP`、`topK`、`candidateCount`、`maxOutputTokens`、`stopSequences`、`responseMimeType`、`responseSchema`、`responseJsonSchema`、`responseModalities`、`mediaResolution`、`seed`、`thinkingConfig`、`responseLogprobs`、`logprobs`、`presencePenalty`、`frequencyPenalty`、`enableEnhancedCivicAnswers`、`speechConfig`

- **默认值**：`{}`（不注入）。
- **怎么改**（典型用法）：

  ```yaml
  # 长解码：>65536 才触发 Gemini 4 长解码（long decode）
  officialParams:
    generationConfig:
      maxOutputTokens: 131072

  # 成本档位 + 图片分辨率
  officialParams:
    serviceTier: flex          # "standard" / "flex" / "priority"
    generationConfig:
      mediaResolution: MEDIA_RESOLUTION_HIGH    # MEDIA_RESOLUTION_LOW / MEDIA_RESOLUTION_MEDIUM / MEDIA_RESOLUTION_HIGH（较新模型另支持 MEDIA_RESOLUTION_ULTRA_HIGH）
  ```

- **改了会怎样（注入语义）**：**顶层键覆盖 SDK 同名字段**；`generationConfig` **按子键合并**——SDK 已发的键（如 pi-ai 设置的 `thinkingConfig`）保留，只覆盖你写的子键。
- **字段价值参考**：

  顶层键（直接写进请求体）：

  | 字段 | 用途 | 相对价值 |
  |---|---|---|
  | `generationConfig` | 下面 generationConfig 子字段的入口（按键合并，不覆盖无关字段） | — |
  | `serviceTier` | `flex` / `standard` / `priority`：吞吐与成本档位 | 高（成本/延迟控制） |
  | `cachedContent` | 引用已创建的上下文缓存（`cachedContents/...`），长上下文省钱 | 中（需先在 Google 侧建缓存） |
  | `toolConfig` | 覆盖工具调用配置（如 `functionCallingConfig.allowedFunctionNames`） | 中低 |
  | `labels` | 计费/统计标签 | 低（无害） |

  `generationConfig` 内可用（建议只写确实需要的）：

  | 字段 | 用途 | 相对价值 |
  |---|---|---|
  | `maxOutputTokens` | 覆盖 DSH 的 65536；**>65536 才会启用 Gemini 4 长解码（long decode）** | 高（长任务） |
  | `thinkingConfig` | `includeThoughts` / `thinkingLevel` / `thinkingBudget` 覆盖 | 中（成本/深度微调） |
  | `mediaResolution` | 图片输入分辨率档：`MEDIA_RESOLUTION_LOW` / `MEDIA_RESOLUTION_MEDIUM` / `MEDIA_RESOLUTION_HIGH`（较新模型另支持 `MEDIA_RESOLUTION_ULTRA_HIGH`），影响视觉成本。⚠ 必须写完整枚举名（本插件按官方 REST 枚举原样透传，写 `low`/`high` 会被 API 以 400 拒绝） | 中（图片多时） |
  | `responseModalities` | `["TEXT"]` / 含 `IMAGE` 的多模态输出 | 中（图像生成模型） |
  | `responseMimeType` / `responseSchema` / `responseJsonSchema` | 结构化输出；对聊天/工具调用通常不需要 | 低 |
  | `temperature` / `topP` / `topK` | 采样参数；Gemini 4 对采样参数基本不敏感（temperature 已在日志里出现忽略提示） | 低 |
  | `seed` | 可复现性 | 低 |
  | `stopSequences` | 提前截断 | 低（易伤输出） |
  | `candidateCount` | 候选数；流式场景基本不可用 | 低 |
  | `responseLogprobs` / `logprobs`、`presencePenalty` / `frequencyPenalty`、`speechConfig`、`enableEnhancedCivicAnswers` | 小众/音频专用/已被忽略 | 不建议 |

  **不建议透传的字段**：`topP`/`topK`/惩罚项/logprobs 在本用途下收益极低；`candidateCount` 与流式冲突；`stopSequences`、`seed` 容易引入难排查的行为差异。确实要时再写，插件只做校验与透传，不替你做语义补偿。`tools`、`systemInstruction` 由 pi-ai/DSH 管理，**不在白名单内**。
- **常见错误与 400 特征**：键名拼错/不在白名单 → **挂载期抛错**（启动日志有 `[gemini-parameter]` 白名单报错）；值或枚举与当前 API 版本不符 → 上游 **400 `INVALID_ARGUMENT`，消息通常点名错误字段**——插件不校验 Google 字段级语义，先删该键或对照官方 `GenerateContentRequest` 文档改值。

### 3.8 `debugDumpTo` — 调试转储

- **含义**：每命中一个被处理的请求，向 JSONL 文件追加一行记录。排障首选（§2 证据 1）。
- **数据类型**：文件路径字符串，或 `null`。
- **取值范围**：任意可写路径；`null` / 不写 = 关闭。
- **默认值**：`null`。
- **怎么改**：

  ```yaml
  debugDumpTo: 'C:\Users\<你>\AppData\Local\Temp\gemini-parameter-dump.jsonl'   # 示例，任意可写路径皆可
  ```
- **改了会怎样**：每行字段：`time` / `instance` / `call` / `url` / `status` / `injected` / `mode` / `xServerTimeout` / `safetySettings`（实际注入值，关闭时 `null`）/ `officialParams`（配置对象，未注入时 `null`）/ `error`。**不记录 prompt 内容**。**正常每个 agent step 有两行**（主请求 + 会话标题生成）；行数异常先查路由与 `hosts`/`endpoints` 命中。
- **常见错误**：路径不可写只 warn 不阻塞请求（但也写不进）；排障完记得改回 `null`，避免文件无限增长。无上游 400 风险。

### 3.9 `log` — 注入日志

- **含义**：每注入一个请求，在宿主日志打一行。
- **数据类型**：布尔。
- **取值范围**：**严格 `true` 才开启**；不写、`false` 均关闭。
- **默认值**：`false`。
- **怎么改**：

  ```yaml
  log: true
  ```
- **改了会怎样**：`dsh web` 启动终端/日志文件里出现 `[gemini-parameter]` 注入行（注入了哪几组、URL；不含 prompt）。
- **常见错误**：写 `on` / `yes` / `1` 之类的 YAML 宽松真值——**只有字面 `true` 开启**。无上游 400 风险。

### 3.10 `onUnsupportedBody` — 不支持请求体的处置

- **含义**：请求体不是可解析 JSON（如流式 body）时怎么办。
- **数据类型**：字符串枚举。
- **取值范围**：`skip`（默认，放行不处理）/ `error`（抛 `GeminiParameterError`，用于排查“为什么没注入”）。
- **默认值**：`skip`。
- **怎么改**：

  ```yaml
  onUnsupportedBody: error
  ```
- **改了会怎样**：`error` 模式下不支持的请求会**直接失败**——只建议排查时临时开启，查完改回 `skip`。
- **常见错误**：长期开着 `error`，把别的问题误判成插件故障。无上游 400 风险（这是插件本地行为）。

### 3.11 常用组合示例

保持默认（四类低阈值 + 超时头），什么都不用写。

只要长解码、不要低阈值：

```yaml
safetySettings: false
officialParams:
  generationConfig:
    maxOutputTokens: 131072
```

成本优先（`flex` 档位 + 关闭阈值）：

```yaml
safetySettings: false
officialParams:
  serviceTier: flex
```

不需要低安全阈值、但需要 `X-Server-Timeout`：

```yaml
safetySettings: false
serverTimeoutSeconds: 1200
```

### 3.12 配置面板（插件详情页配置区）

- 配置入口在 **DSH 插件页的本插件详情内**：**DSH 设置 → 插件 → 点开 `dsh-gemini-parameter`**，详情页上部是插件介绍（宿主自动渲染的 `package.json` description），**介绍下方的配置区**即本插件面板——可查看当前配置概览、编辑、保存、还原默认、打开配置文件；再往下是宿主自带的行开关/版本/来源区块，整页文档流原生滚动。
- **保存写回插件包自身的 `cordis.patch.yml`** 的 `config:` 段，且需**重启 `dsh web`** 后生效（配置在挂载期读取，面板保存 ≠ 立即生效）。
- 保存与还原默认由**服务端权威校验**，写入走“时间戳备份 → 临时文件 → 原子改名 → 回读校验”管线，备份文件在包目录的 `.config-backups\` 内。
- **配置不在 `~/.dsh/profiles/<名称>/cordis.patch.yml`**——profile 层补丁只用于停用插件行（见 §6）；配置随包安装，在插件包目录内。
- 面板架构（双半区、RPC 服务、保存管线、`plugins.bundle.config` 槽挂载）见 `维护文档.md` 的“配置面板架构”。面板只是编辑配置的另一个入口，**它打不开或保存失败都不影响参数注入主功能**。

## 4. 本插件不解决的问题

**Google 的 `stream ended without a finish reason`（流式响应没有 `finishReason` 就结束）不在本插件解决范围内。**

- 该问题的成因是 **Google 的响应格式与 DSH 解析层之间的潜在不兼容**（DSH 期望流以带 `finishReason` 的块收尾），不是“请求缺少某个官方参数”。因此透传 `safetySettings`、`generationConfig` 等字段**无法解决**它。
- 该问题请使用 [TikaFlow/dsh-model-fix](https://github.com/TikaFlow/dsh-model-fix) 处理（针对 DSH 侧模型/流式解析的修复）。
- 两件事互不替代、可以同时使用：本插件负责“把 Google 官方参数发出去”，`dsh-model-fix` 负责“修 DSH 侧的流式收尾解析”，二者在不同层，不冲突。

## 5. 常见问题

**Q：配置到底在哪个文件改？**
A：**插件包自身的 `cordis.patch.yml`**（安装目录内，`config:` 段），改完重启 `dsh web`。不在 `~/.dsh/profiles/<名称>/cordis.patch.yml`——那是 profile 层补丁，只用于停用插件行。详见 §3.1；配置面板（见 §3.12）保存的也是包内这个文件，改配置首选面板。

**Q：会不会影响 web 搜索、图片下载、MCP 等其它网络请求？**
A：不会。只匹配 `hosts` + `endpoints`（默认仅 `generativelanguage.googleapis.com` 的 `:generateContent` / `:streamGenerateContent`），其余请求连 body 都不读，直接透传。

**Q：会不会重复注入导致 400？**
A：不会。`safetySettings` 按 category 去重合并，`generationConfig` 按键合并；body 被改写时会删除 `content-length` 让 fetch 重算；卸载时 disposer 只在 fetch 仍是自己那层时还原，不影响其它插件。

**Q：`X-Server-Timeout` 到底有没有用？**
A：它是 Vertex AI 的官方头（服务端处理时限，1..1200 秒）。对 `generativelanguage.googleapis.com` 实测 `1200` 与 `200` 均被接受（200 响应）、传 `0` 返回 400，但 Google 未公开它在该端点上的具体语义。按“附加保险”使用，不要当作可靠性保证。

**Q：`officialParams` 传了不被支持的字段会怎样？**
A：插件层只做白名单与 JSON 校验，不校验 Google 的字段级语义；上游会返回 400（`INVALID_ARGUMENT`，消息通常点名错误字段）。先删该键，或到 Google 官方 `GenerateContentRequest` 文档核对枚举值。

**Q：为什么配置里没有 `xhigh` 思考档？**
A：与本插件无关。pi-ai 的 Google 映射表里没有 `XHIGH`（`dist/api/google-shared.js` 只有 UNSPECIFIED/MINIMAL/LOW/MEDIUM/HIGH），声明 `xhigh` 会在请求前抛 `Unsupported Google thinking level mapping`。等上游补枚举后再在模型条目的 `reasoningEfforts` 里加。

**Q：插件会不会在 DSH 升级后失效？**
A：有失效风险，属“依赖上游实现细节”的插件。检测与处置见 `维护文档.md` 的“上游依赖与脆弱点”。

**Q：为什么不建一个代理来改参数？**
A：不需要。本插件只处理 DSH 直连 Google 的原生路由，在进程内完成；同理也没有额外端口、额外进程和额外故障点。DSH 原生本就缺少这些官方参数的设置入口，补这一层就够了。

## 6. 停用 / 卸载

```powershell
# 临时停用（在 profile 层覆盖“插件行”，不改本包）
# 在 ~/.dsh/profiles/<名称>/cordis.patch.yml
# （Windows：<用户目录>\.dsh\profiles\<名称>\cordis.patch.yml）末尾加：
# - id: gemini-parameter
#   disabled: true

# 彻底卸载
dsh plugin --profile <名称> remove dsh-gemini-parameter
```

注意：上面的 profile 层写法只用于**停用插件行**；**配置不在这个文件里**（见 §3.1 / §3.12），写进去不会生效。

卸载后 `globalThis.fetch` 会还原为原始实现；已经发出的请求不受影响。

## 7. 升级与重装须知

- 升级或重装（重新执行 `dsh plugin --profile <名称> add github:FatBadger217/dsh-gemini-parameter`，或 `remove` 后重新 `add`）会**整体替换插件包目录**（DSH 内置 pnpm 的虚拟 store 机制）。这意味着：
  - 包内 `cordis.patch.yml` 的**手工修改内容**会被新版本的默认配置覆盖；
  - 配置面板自动生成的备份目录 `.config-backups\` 会一并丢失。
- **升级前先导出/复制配置**：用配置面板的“打开配置文件”定位包内 `cordis.patch.yml`，复制或另存一份；升级后把 `config:` 段改回（或用配置面板重新编辑保存），再重启 `dsh web`。
