# 维护文档 — dsh-gemini-parameter

面向维护者：设计决策、代码地图、上游依赖与升级风险、验证与排障。

当前版本 **0.1.1**（2026-11-22）；版本历史见 [`../CHANGELOG.md`](../CHANGELOG.md)。文中 `<repo>` 指本仓库根目录，插件安装后位于 profile 的 `node_modules\dsh-gemini-parameter\`（下称安装目录）。

## 0. 用途、边界与免责声明（务必先读）

> **本插件不是破甲插件。**

- 透传的是 Google **官方支持** 的 `safetySettings` 参数（阈值如 `BLOCK_NONE`），用途是让 Google 官方在内容安全判定上对敏感内容放宽限制；不是绕过/破解模型，也不含提示词注入。
- **破甲相关提示词极易触发 Google 官方云端掐断**（流中断、`finishReason` 异常、`429`/安全拒绝），属上游行为，本插件不改变也不保证通过。
- **降低安全阈值 ≠ 任何内容都能生成**：CSAM、暴恐、严重暴力等在任何阈值下都无法通过 Google 强制拦截，尝试会导致封号并可能承担法律责任。
- **免责声明**：本插件只做官方参数透传；使用者若用于违法犯罪行为，后果自负，与作者无关。

## 1. 目标与硬约束

- **目标**：补上 DSH 原生 `google` 路由缺失的 Google 官方参数透传能力——按需为每次 Gemini 请求（含流式）注入 `safetySettings`、`X-Server-Timeout`，以及白名单内的其它 `GenerateContentRequest` 字段（`serviceTier`、`cachedContent`、`maxOutputTokens`、`mediaResolution` 等）；三组可独立开关。
- **约束**：不修改 DSH / pi-ai / `@google/genai` 安装包；零运行时依赖；可热重载、可干净卸载；失败时不能把普通 HTTP 流量搞坏。

## 2. 为什么是 fetch 包装（而不是 adapter / onPayload）

调研结论（基于 dsh 0.2.2-rc.1、pi-ai 1.5.0、@google/genai 2.21.0）：

1. **自定义 provider/adapter 不可行**：`dsh-llm` 有 `DUPLICATE_ADAPTER` 校验（`lib/index.js:1872`），`dsh-llm-pi-ai` 不支持 `api: google-generative-ai`（`lib/index.js:835-839, 931`）。
2. **`onPayload` 没有接入口**：pi-ai `dist/api/google-generative-ai.js:45` 确实调用 `options?.onPayload?.(params, model)`，但 DSH 的 pi-ai 适配层调用 `models.streamSimple` 时不传 `onPayload`（`dsh-llm-pi-ai/lib/index.js:2025-2032`），profile schema 封闭（无 `extraBody`）。monkey-patch `ModelsImpl.prototype.streamSimple` 可行但依赖内部实现，脆弱。
3. **fetch 是最窄且有效的点**：`@google/genai` 的 `DEFAULT_FETCHER`（`dist/node/index.mjs:19122`）在调用时解析全局 `fetch`，实际请求走 `dist/node/index.mjs:13877` 的 `await fetch(url, {...})`；body 为 JSON 字符串。改 `globalThis.fetch` 即可覆盖全部 Gemini 协议请求，且不影响别的客户端。
4. 反向约束：pi-ai **明确拒绝**自定义 fetch（`dist/api/google-generative-ai.js:36-38`：`if (options?.fetch && options.fetch !== globalThis.fetch) throw ...`）。所以不能走“给 provider 传 fetch”的路线，只能包装全局对象。

## 3. 装载机制

- 本包是 bundle：`package.json` 的 `dsh.bundle.patch` → `cordis.patch.yml` 里一条 `insert` 行（`id: gemini-parameter`, `name: dsh-gemini-parameter`, `config: ...`）。
- 安装由 `plugin_manager install_bundle`（或 `dsh plugin --profile <名称> add dsh-gemini-parameter`——npm 来源；或 `add github:FatBadger217/dsh-gemini-parameter`——GitHub 源码）完成：写 profile `package.json` 的 `dsh.profile.bundles` 与 `dependencies`，包体由 DSH 内置 pnpm 安装到 profile 的 `node_modules\dsh-gemini-parameter\`。**升级/重装会整体替换安装目录**：包内 `cordis.patch.yml` 的手工修改与 `.config-backups\` 备份随之丢失（用户侧提醒见 `使用说明.md` §7）。
- 插件入口导出 `apply(ctx, config)`（无 `inject`、无 `Config` schema，配置在 `normalizeConfig` 里手动校验）。`ctx.effect(() => () => { ... })` 注册还原 fetch 的 disposer，插件卸载时自动执行。
- 未声明 `Config` 是刻意的：`@deepseek-ai/schemastery` 不在 profile 的可解析路径上（junction 安装后按真实路径解析），为保持零依赖改为 apply 时校验。
- 本插件是**双半区插件**（宿主半区 + 客户端半区），客户端经 `dsh.client` 声明发现（`dsh.client.inject` 只需 `["@deepseek-ai/dsh-client-locale"]`）；客户端半区唯一注册 `plugins.bundle.config` 槽，详见 §6。

## 4. 代码地图（`lib/index.js`，单文件约 400 行）

| 区块 | 作用 |
|---|---|
| `DEFAULT_* / VALID_*` | 默认主机、端点、四类安全设置、阈值白名单、hostname/category 正则 |
| `normalizeConfig(raw)` | 校验并冻结配置；非法值抛 `GeminiParameterError`（挂载期失败，不静默） |
| `applySafetySettingsToBody(body, settings, mode)` | 纯函数：`merge` / `replace` / `insert-only`；返回 `{changed}` |
| `resolveUrl / matchesUrl` | 从 string、URL、Request 取 URL；host + path 后缀匹配（支持 `*.` 通配） |
| `readBodyText` | 支持 string / Blob / ArrayBuffer / TypedArray / Request.clone()；`URLSearchParams`、`ReadableStream` 明确跳过 |
| `OFFICIAL_TOP_LEVEL_KEYS / OFFICIAL_GENERATION_KEYS` | 允许透传的官方字段白名单（顶层 5 个、`generationConfig` 19 个） |
| `cloneJson(value, label)` | 深拷贝配置值并校验 JSON 可序列化 |
| `normalizeOfficialParams(value)` | 校验并冻结 `officialParams`；未知键、空 `generationConfig`、非 JSON 值直接报错 |
| `applyOfficialParamsToBody(body, params)` | 纯函数：顶层键覆盖、`generationConfig` 按键合并；返回 `{changed}` |
| `createPatchedFetch(baseFetch, config, hooks)` | 包装器主体：加头、解析并注入三组参数、调用原 fetch、可选 debug dump；返回 `{fetch, stats}` |
| `apply(ctx, config)` | 挂载：替换 `globalThis.fetch`、`ctx.effect` 注册还原、打印激活日志 |

关键实现细节：

- **header 处理**：先 `new Headers(init?.headers ?? request?.headers)` 复制；`X-Server-Timeout` 已存在则不覆盖；body 被改写时删除 `content-length`，避免长度不符。
- **body 改写**：只在 JSON 对象上注入；改写后用 `JSON.stringify` 回写；`mode: merge` 下已有 category 被我们的阈值覆盖、缺失的补齐，未知类别原样保留。
- **Request 分支**：`input` 为 `Request` 时用 `new Request(requestLike, options)` 重建，原 Request 不消费；`body` 为流时不处理。
- **debug dump**：仅当 `debugDumpTo` 非空；记录 URL、HTTP 状态、`injected`、`xServerTimeout`、最终 `safetySettings`，**不记录 prompt**。`instance`/`call` 字段用于区分“同一宿主内两次真实请求”与“嵌套包装”。
- **幂等与还原**：还原时检查 `globalThis.fetch === patched.fetch`，不覆盖后装的插件；两套装本插件会嵌套包装但注入结果相同（`changed=false` 幂等）。
- **三组独立开关**：`safetySettings !== null` 才注入安全阈值；`serverTimeoutSeconds !== null` 才加头；`officialParams` 非空才写字段。三组都未生效时直接透传，不读写 body。
- **stats 字段**：`matched`（命中 URL 数）、`injected`（安全阈值改写次数）、`paramsInjected`（officialParams 改写次数）、`timeoutHeaders`、`unsupported`、`failed`。
- **面板配套**：`lib/config-file.js`（配置文件读取与保存管线）、`lib/reveal.js`（在文件管理器中打开配置文件）、`lib/panel-core.js` + `lib/panel-service.js`（面板 RPC 服务）、`lib/client.js`（客户端半区：只注册 `plugins.bundle.config` 槽、渲染插件详情页配置区）——见 §6。

## 5. 按需透传语义

| 组 | 默认 | 关闭方式 | 注入位置 |
|---|---|---|---|
| `safetySettings` | 四类 `BLOCK_NONE` | `safetySettings: false` | body 顶层 `safetySettings` |
| `X-Server-Timeout` | `1200` | `null` / `false` / `0` | 请求头 |
| `officialParams` | 空（不注入） | 省略或 `{}` | body 顶层 + `generationConfig` 子键 |

- **白名单**：顶层 `generationConfig` / `serviceTier` / `cachedContent` / `labels` / `toolConfig`；`generationConfig` 内 19 键（完整列表见 `cordis.patch.yml` 注释）。
- **合并语义**：`safetySettings` 沿用 merge / replace / insert-only；`generationConfig` 按键合并，SDK 已发的其它键保留；顶层键覆盖 SDK 同名字段。
- **故意不做透传**：`tools` 与 `systemInstruction` 由 pi-ai/DSH 管理，强行覆盖会与工具调用和系统提示冲突。
- **校验时机**：全部在挂载期（`normalizeConfig`）完成；非法配置使插件挂载失败，而不是在请求路径上做半校验。

## 6. 配置面板架构

fetch 注入主功能之外的**配置面板**挂在**插件详情页配置区**（用户侧说明见 `使用说明.md` §3.12）。要点：

- **双半区插件**：
  - 宿主半区 `lib/index.js`——fetch 包装主功能 + 面板的宿主侧 RPC 服务；
  - 客户端半区 `lib/client.js`——运行在 DSH web 前端的配置区 UI；
  - `package.json` 声明 `dsh.client` 字段与 `exports["./client"]`，DSH web 客户端按此发现并加载客户端半区；`dsh.client.inject` 只需 `["@deepseek-ai/dsh-client-locale"]`（见下“槽名是自由字符串”）。
- **挂载机制（`plugins.bundle.config` 槽契约）**：
  - 客户端半区**不注册 `sidebar.panellist` / `main` 槽**，唯一注册：`slots.register({ name: "plugins.bundle.config", key: "dsh-gemini-parameter", locale: NS, inject: face }, 组件)`；
  - 消费方是官方插件管理页 **`@deepseek-ai/dsh-client-ui-plugin-manager`**（DSH 内置，无需 profile 声明）：用户在 设置→插件 页点开 dsh-gemini-parameter，先显示插件介绍（= `package.json` 的 `description`，宿主自动渲染），下方 `<section data-plugin-config>` 里 `renderSlot("plugins.bundle.config", { view: "page" }, { entryKey: pkg.name })` 渲染我们的配置 GUI，再往下是宿主自带的行开关/版本/来源区块；
  - **configured 判定**：插件页从 `plugins.bundle.config` 槽登记项的 `options.key` 收集集合——注册 `key` = 包名即出现配置区，完全自控；
  - 槽契约：`key` = 包名（`dsh-gemini-parameter`）；组件 props 为 `{ t, view }`，`view: "page"` = 插件详情页配置区，`view: "summary"` = 摘要形态（当前未使用）；
  - **槽名是自由字符串**：注册槽不需要在 `dsh.client.inject` 里声明槽的“拥有者包”——参照 dsh-console-plugin 只声明 locale+settings 就注册了 4 种槽；因此 `dsh.client.inject` 保持只含 locale。
- **布局约束**：配置区组件**禁视口化布局（`fixed` / `100vh` / `overflow:hidden`）**，整页文档流原生滚动（由插件管理页滚动）；**唯一允许的 `fixed` 是确认对话框遮罩**。（此前的侧栏+主区挂载形态因占主区与主区容器滚轮失效被否决。）
- **明确不做**：`plugins.bundle.activation` 摘要槽、`plugins.row.config` 行摘要槽、`settings.section` 设置分区。
- **宿主 Typert RPC 服务 `geminiParameterPanel`**，四方法：
  - `getInfo`——读取当前配置与元信息供面板展示；
  - `saveConfig`——保存面板编辑后的配置；
  - `resetDefaults`——还原默认配置；
  - `revealConfigFile`——在系统文件管理器中打开配置文件。
- **保存管线（防写坏）**：`saveConfig` / `resetDefaults` 走“**时间戳备份现有文件 → 写临时文件 → 原子 rename 覆盖 → 回读校验**”，任何一步失败即中止并保留原文件。保存目标始终是**插件包自身的 `cordis.patch.yml`** 的 `config:` 段——**不是** profile 的 `cordis.patch.yml`。
- **保存后仍需重启 `dsh web`**：插件配置在挂载期读取一次，面板保存 ≠ 立即生效。
- **挂载与降级（三级解析 + 动态注入子 fiber；实证结论）**：
  - `lib/index.js` 用**动态 `import('./panel-service.js')`** 挂载面板——静态 import 会让本地 `npm test` 直接 ModuleNotFound；
  - `lib/panel-service.js` 对 `@deepseek-ai/dsh-typert-protocol` 做**三级异步解析**：① bare 动态 import（DSH Loader 解析通道可用时）；② 从宿主进程入口（`process.argv` 中指向 `@deepseek-ai\dsh\` 的前缀，或 `DSH_ROOT` 环境变量）用 `createRequire` 在 dsh 安装目录的 `node_modules` 里解析后按 `file://` URL import。实证：路径挂载/junction 安装的插件不走 Loader 的 bare 解析通道，必须靠②；
  - 服务注册用 cordis 的**动态注入** `ctx.inject(['typert'], cb)`（cordis/lib/index.js `inject()` 方法）——子 fiber 只在 typert 服务可用时启动；**绝不能给插件声明静态 `inject: ['typert']`**，那会让整个插件（含 fetch 注入）等 typert 才启动；
  - **任何一级失败只记日志/写转储，不影响 fetch 注入主功能**——两半区解耦，主功能零回归风险；
  - 排障证据：`dumpPanelState` 把面板注册结果写一行 JSONL 进 `debugDumpTo`（字段 `panel: "geminiParameterPanel"`，state ∈ `subfiber-scheduled`/`registered`/`typert-unresolved`/`failed`/`load-failed`），headless 无日志环境也能看到。
- 客户端契约由 `test/client-smoke.test.mjs` 固化（只注册 `plugins.bundle.config`、key=包名、face 含 `t`/`loadInfo`/`saveConfig`/`resetDefaults`/`revealConfigFile`）。

## 7. 上游依赖与脆弱点（升级必读）

| 依赖 | 位置 | 若变化会怎样 | 检测方法 |
|---|---|---|---|
| `@google/genai` 调用时解析全局 fetch | `dist/node/index.mjs:19122` `DEFAULT_FETCHER`、`:13877` `await fetch(...)` | 若改成模块加载时缓存 fetch 或换 node http，注入静默失效 | `debugDumpTo` 不再产生行 / `log: true` 无日志 |
| `@google/genai` body 为 JSON 字符串 | 同文件请求构造处 | 若改成流式 body，`readBodyText` 返回 null → 只在 `unsafe` 时跳过 | dump 里 `injected=false` 且 stats.unsupported 增长 |
| `@google/genai` 允许 `safetySettings` 顶层字段 | v1beta REST 语义 | Google 若改 schema，请求 400 | upstream 返回 `INVALID_ARGUMENT` 且消息指向 safetySettings |
| pi-ai 拒绝自定义 fetch | `dist/api/google-generative-ai.js:36-38` | 不要试图通过 options.fetch 传入；DSH 若开始传 `fetch`，可能抛 `Custom fetch is not supported` | 请求前直接报错 |
| DSH 版本 | `@deepseek-ai/dsh` 0.2.2-rc.1 | 升级后 profile 结构与 `ctx.effect` API 可能变 | `dsh --profile web --dump-config` + `plugin_manager list_plugins` |
| `X-Server-Timeout` 语义 | 官方文档为 Vertex AI（1..1200s） | 对 AI Studio 端点未公开；`0` 会 400 | 实测 `400` 时把 `serverTimeoutSeconds` 设 `null` |
| `officialParams` 字段名/枚举 | Google REST `GenerateContentRequest` | 字段改名或枚举变化 → 上游 400 | 上游 `INVALID_ARGUMENT` 点名该字段时，对照官方文档修正白名单或取值 |
| billion-context 改写 URL 形状 `/bili/<原始URL>` | 其 `native-intercept` 层重写 loopback 代理地址（上游分析 [#7527](https://github.com/ranxianglei/billion-context/issues/7527)） | `/bili/` 前缀变形 → `relayUnwrap` 解包失败、注入重新静默失效 | 面板"代理改写（未兼容）"计数回升；对照 bili 日志 `forward POST →` 行核对路径形状 |

**与 billion-context 的共存机制（0.2.0 起）**：bili 的 native intercept 把模型请求 URL 重写为 `<loopback>/bili/<原始URL>` 后仍交回全局 fetch 链——本插件的包装层**看得到**这些请求，只是按原始主机匹配不上。`relayUnwrap: ['/bili/']` 开启后从路径解出内嵌原始 URL 再做主机+端点匹配（`unwrapRelayUrl`），注入发生在送入 bili 代理**之前**的请求体上，由代理转发到真实上游。`relaySpotted` 统计在兼容关闭时对含 `/bili/` 的请求计数，面板据此提醒。**脆弱点**：该 URL 形状是 bili 内部约定而非公开契约；若 bili 未来提供官方"原始上游 URL"header 或内置注入通道（issue #7527 方向 b/2），应迁移过去。

**升级检查清单**（每次升级 DSH 或 pi-ai 后各跑一次）：

## 8. 排障表

| 症状 | 可能原因 | 处置 |
|---|---|---|
| 插件行存在但 `fiberPhase` 不是 active | apply 抛错（配置非法）、包未链接、profile 需重启 | 看宿主日志里的 `[gemini-parameter]` 报错；`dsh --profile web --dump-config` 看 config；重启 dsh web |
| dump 没有新行 | 请求没走 google 原生路由 / 端点不匹配 / fetch 被别的插件先包了且未透传 | 确认 provider 是 `google`；`hosts`/`endpoints` 配好；临时改 `log: true` |
| dump 有行但 `injected=false` | 请求体不是 JSON、或已是同值（幂等返回 changed=false） | `onUnsupportedBody: error` 观察异常；`mode: replace` 验证改写链路 |
| Google 返回 400 指向 `safetySettings` | 类别名或阈值不被该模型支持 | 去掉该类别或改 `BLOCK_ONLY_HIGH`；`onUnsupportedBody: skip` |
| 请求挂起/超时 | 插件在 fetch 前做了额外 await（仅 debug dump 时） | 关 `debugDumpTo` 后重试；确认 dump 路径可写（不可写只 warn 不阻塞） |
| 其它网络功能异常 | 匹配范围被放大（hosts 通配过宽 / endpoints 写成了空串） | 恢复默认 `hosts`/`endpoints`；单元测试覆盖了“非 Google 不触碰” |
| dump 里 `officialParams` 为 null 但配置已写 | 配置未重载、键名拼错（挂载期会报错）、或请求未命中 `hosts`/`endpoints` | 重启 dsh web；看宿主日志里的白名单报错；确认路由为原生 `google` |
| 上游 400 且点名某个 `officialParams` 字段 | 字段名/枚举与当前 API 版本不符 | 删除该键或按官方文档改值；插件不做字段级语义校验 |
| 插件详情页配置区不出现 | 没在插件页点开本插件；client 半区未随宿主加载（改完需重启 `dsh web` + 刷新页面）；`configured` 由槽注册决定（注册 key=包名即出现） | 确认在 设置→插件 页点开 `dsh-gemini-parameter`；重启 `dsh web` 并刷新 GUI；配置区只是编辑入口，**不出现不影响 fetch 注入主功能**，可手工编辑包内 `cordis.patch.yml` |
| 配置区保存失败 / 还原默认失败 | 配置文件被占用/只读、磁盘满 | 面板只是编辑入口，**失败不影响 fetch 注入主功能**；可改用手工编辑包内 `cordis.patch.yml` + 重启；保存管线的备份文件带时间戳，在包目录内 |
| 面板出现"代理改写（未兼容）"警告 / 统计全是 0 但模型正常工作 | 装了 billion-context 等改写型代理，请求 URL 被重写为 `<loopback>/bili/<原始URL>`，`hosts` 匹配不上 | 在配置面板"网络匹配"区给 `relayUnwrap` 添加 `/bili/`，保存并重启；详见 README"与 billion-context 共存" |

## 10. 开发与贡献流程

常规开源流程：

1. fork / clone 仓库到本地（`<repo>` 指仓库根目录）；
2. 在 `<repo>` 内修改 `lib\` / `test\` / `docs\` / `cordis.patch.yml`；
3. `npm test` 全绿（37 项，已含客户端冒烟）；
4. 提交并发 Pull Request，说明动机与验证结果。

本地试验可自选手段（例如在临时 profile 以 `file:` 形态安装本包目录验证真实链路），但不要把个人路径写进仓库文件。
